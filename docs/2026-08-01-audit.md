# margostat audit — 2026-08-01

> The next round, after the fixes described below: [`2026-08-01-audit-2.md`](2026-08-01-audit-2.md).

Scope: logic, UX, code, the authenticity of the data, what to remove and what to add.
Covered: all the code (`src/*.ts`, `public/index.html`), all the data
(20 worlds × 9 snapshots, 620 MB) and a comparison against the live margonem.pl.

## 1. Is the data real? — YES, confirmed

The `aether/2026-07-21` snapshot compared against the live ranking (as of 2026-08-01):

| # | snapshot 21.07 | live 01.08 | agreement |
|---|---|---|---|
| 1 | essobe 378 (tropiciel), PH 8749 | essobe 378**t**, PH 9550 | ✅ |
| 2 | kamillek kox 359 (paladyn) | kamillek kox 362**p** | ✅ +3 lvl |
| 3 | Bandyta Brunt 347 (wojownik), PH 109614 | Bandyta Brunt 348**w**, PH 109715 | ✅ |
| 5 | Dizzard 335 (tancerz ostrzy) | Dizzard 335**b** | ✅ |
| 8 | Kacperxo 331 (mag) | Kacperxo 331**m** | ✅ |

Further evidence of consistency:

- the ranks in each snapshot form a continuous 1..N range, the nicknames are unique
  (0 duplicates),
- `rows ≈ pages × 100` (aether 39037/391, gordion 80896/809) — consistent with the pagination,
- 20 worlds × 9 snapshots, complete, with nothing missing and no truncated files,
- between 09.07 and 21.07 (aether): 785 players gained a level, 1 lost one, the rest
  unchanged — a distribution typical of a real game, not of generated data,
- populations fall smoothly (e.g. `fobos` 25037 → 23796), and the profession letters on the
  live page (`t/p/w/b/m`) match the profession codes in the snapshots.

**Verdict: the data is authentic.**

### The exception — the `lastOnline` field is synthetic

`src/world_scraper.ts:155-171` manufactures a precision the source does not have:

- "Mniej niż 24h temu" → the scrape time minus 60 s (faking precision to the second),
- "N dni temu" → the same hour N days back (a false hour, sensitive to DST),
- "20655 dni temu" (139 records in aether alone) = an account never logged into →
  written as a date in 1969.

The only place where a file holds values that look like a measurement while being a
computation. To be replaced with `lastOnlineDays: number | null`.

## 2. Critical — the data size against the GitHub Pages limit

- `public/worlds` = **620 MB**, growing by ~70 MB per scrape round (every ~12 days).
- The hard limit for a published site on GitHub Pages is **1 GB** → about 5 rounds
  (**roughly 2-3 months**) remain before the deploy starts failing.
- On every push to `main`, `deploy.yml` packs and uploads the whole of `public/` as an
  artifact.

Measured on `aether/2026-07-21` (5.09 MB):

| action | size | gain |
|---|---|---|
| current state (pretty-printed, 351,340 lines) | 5.09 MB | — |
| minified JSON (the code has done this since 45413ea, the data has not) | 2.78 MB | −45%, lossless |
| dropping the derived `lastOnline` ISO | ~2.2 MB | −20% |
| gzip (`.json.gz` + `DecompressionStream`) | 748 KB | −85% |
| a level×profession aggregate (everything the dashboard draws today) | **36 KB** | −141× |
| a delta against the previous snapshot (98.7% of players unchanged) | ~a few hundred KB | −10-20× |

The strategy chosen: **aggregates + a one-off recompaction** (620 MB → ~340 MB, no data lost).

> The figures in this section describe the state **before** the fix, and the strategy chosen
> then was replaced along the way by a better one: instead of aggregates plus raw data on
> demand, the snapshot was split into `.f.json` / `.n.json`, which gave **118 MB and ~65
> rounds of headroom** while keeping the filters exact. Details:
> [`2026-08-01-size-budget.md`](2026-08-01-size-budget.md).

## 3. The scraper (`src/world_scraper.ts`)

1. **`parseTotalPages`, candidate 3 (141-145)** — it joins the page numbers into
   `"2 3 4 390"`, and `parseNumber` then strips the spaces → **234390**. If candidates 1-2
   fail, the scraper sets off across 234 thousand pages.
2. **One bad row kills a whole world** — `parseTable` throws on the first anomaly (197-252),
   the retry repeats it 4×, and the world drops out of the entire round in silence.
3. **The scraper is already broken — not "at risk".** Verification against the live page
   (2026-08-01) showed that Margonem changed the ranking after the last scrape:
   - the table has **5 columns** (`#`, Gracz, Poziom, PH, Ostatnio online) — there is no
     "Profesja" column, so the table filter (`txt.includes("Profesja")`) matches nothing →
     every world ends in a `ParseError` while the process still exits with code 0,
   - the profession now lives in `<span title="Tropiciel">378t</span>` in the level column,
   - places 1-3 carry a portrait instead of a rank number in the "#" column,
   - the old URL `/ladder/players,<world>?page=N` 301s to `/ladder/<World>/players`
     **losing `?page=N`** — even following the redirect, the scraper would fetch page 1 over
     and over. The new address: `/ladder/<world>/players?page=N`.
4. **The retry restarts from page 1** (407-429) — for `gordion` (809 pages) that is up to 4
   full passes, ~1 h of requests.
5. **A silent failure** — once the attempts run out, `log("FATAL")` + `return`; the process
   exits successfully and rebuilds the manifest as though nothing had happened.
6. **Local time against UTC** — the filename/manifest/UI say `22-04-12` while the payload
   says `20:04:12Z`.
7. `professionToInt` (174-185) carries an `owca: 6` hack for a broken encoding.
8. No handling of 429/503; `interval` allows 0. A full round is ~5700 pages ≈ 1.6 h at
   1 req/s.
9. Dead code: `stat()` in `rebuildManifest` (288), `split("__")[0]` (292).
10. **No tests at all** — while the parsing functions are pure and trivial to test.

### `src/server.ts` — path traversal

`public${decodeURIComponent(url.pathname)}` (5-11) with no path normalisation:
`curl --path-as-is http://localhost:3000/../src/world_scraper.ts` serves any file. Dev only,
but the fix is 3 lines.

## 4. The dashboard (`public/index.html`)

**The biggest problem: the application is called "player statistics" and does not show a
single player.** There is one bar chart (level × profession) and some counters. Despite 9
snapshots over time there is no comparison over time at all — which is what the snapshots are
collected for.

**Bugs**

- `fillSnapshotSelect` (512) sets `fileInfo` to `files[0]` = the oldest file, while the list
  is reversed and the newest is the one selected.
- `loadSnapshot` (515) has no protection against a race — switching world or date quickly
  while 5-11 MB is being fetched can draw an older payload over a newer one.
- The "Ostatnio online" preset has two options with `value=""` (183 and 191).
- `profCheckbox.checked = "true"` (357) — a string instead of `true`.
- Rows with an unrecognised "last online" are silently dropped even under "Wszyscy" (341-343).

**Performance**

- Every keystroke in the filters (567-569) recomputes 39 thousand rows and does
  `chart.destroy()` + `new Chart()`.
- The default view fetches 5-11 MB of JSON with no loading indicator (a 36 KB aggregate would
  serve the same chart instantly).

**UX / accessibility**

- No responsiveness — `.toolbar-row1` is a rigid `200px 180px 1fr auto` grid (68-73) that
  falls apart below ~600 px. Not one media query in the whole file.
- No loading state, no empty state, and the error is not cleared when the world changes.
- No state in the URL; the copy button copies the URL of the raw JSON, not of the dashboard.
- Professions encoded by colour alone, no `:focus-visible`, no text alternative for the chart.
- Chart.js from a CDN with no SRI and no fallback (7).
- No `<meta name="description">`, no favicon, no `404.html`, no `.nojekyll`.
- The "Filtruj" button (200) is redundant — the filtering is live anyway.

**Dead code**

- `getSelectedProfessions()` (309-312) is unused — `filterRows` duplicates the logic inline.
- Accessors for two row shapes (269-287) and `json.rows ?? json.data ?? json` (524) support
  formats that no longer exist in the data.

## 5. Repo / infra

- `.claude/settings.local.json` is committed — it belongs in `.gitignore`.
- The README links to `https://kamilgrocholski.github.io/chary/` — the link is correct; the
  repository is called `chary` even though the package is `margostat`.
- No scheduled workflow (the scrape is manual, every ~12 days) and no CI — the only workflow
  is the deploy.
- **`luvia` — a live official world missing from `src/worlds.ts`.** The ranking exposes ~57
  worlds in total (the rest are legacy/private servers: alcatraz, arkantes, … whisper).
- Nicknames link to profiles: `/profile/view,6805038#char_729,aether` → **there is a stable
  character ID**, and it is not stored today. Without it, following a player rests on the
  nickname (the one level drop of −9 detected in aether is probably a collision or a nickname
  change).

## 6. What to skip / remove

- the derived `lastOnline` ISO in the rows → `lastOnlineDays: number | null`,
- pretty-printing in the historical files (a one-off recompaction, −280 MB),
- the "Filtruj" button, `getSelectedProfessions`, the legacy accessors, the `json.data`
  fallback,
- `stat()` in `rebuildManifest`, `split("__")`, the `owca: 6` hack,
- `.claude/settings.local.json` out of git.

## 7. What to add

- **aggregates** (level × profession × activity) — the dashboard loads 36 KB instead of 5 MB,
- **a player table + a search by nickname** (today not one player is visible),
- **progression over time** — a player's level/honor/rank across 9 snapshots; needs `char_id`,
- **the top N changes** between snapshots (the biggest gains, the honor leaders),
- **population trends** and comparisons between worlds (`fobos` −5% in 3 months),
- **an activity distribution** (<24h / 7 days / 30 days / "never"),
- unit tests for the parsers plus a fixture of a real ranking page, `--dry-run`,
- CI: typecheck + tests; a scheduled scrape (only once the size problem is solved).

## 8. What was fixed (2026-08-01)

The agreed scope: the audit plus the critical fixes. New features (a player table, a player's
progression over time, the top N changes) deliberately did **not** go in — they are left for
later.

**The scraper**
- The parsing was moved into `src/parser.ts` and rewritten for the new markup (5 columns, the
  profession from `title`, the rank reconstructed for places 1-3, the `charId` from the
  profile link).
- A corrected ranking address plus detection of the redirect that loses the pagination.
- `parseTotalPages`: `Math.max` over the page numbers instead of joining digits.
- Faulty rows are skipped and counted; a world aborts only above 1% of bad rows on a page.
- Retrying **per page** (with `Retry-After`), instead of rewinding a whole world to page 1.
- A failed world → a summary and **exit 1** instead of a silent success.
- A new row schema, v2: `lastOnlineDays` instead of an invented ISO timestamp, plus `charId`.
- `--dry-run` checks the parser on page 1 of every world without writing anything.
- Parser tests against a capture of a real page (`test/fixtures/ladder-aether-p1.html`).

**The data**
- The history was recompacted and then the snapshot was split into two files sharing one row
  order: `<ts>.f.json` (level/profession/honor/days) and `<ts>.n.json` (nicknames + `charId`).
  The rank follows from the order, so it is not stored.
- **620 MB → 118 MB**, a lossless migration (verified row by row against the originals in
  git). Growth per round: 38.6 MB → 13.9 MB, i.e. ~10 rounds of headroom against the Pages
  limit became ~65 (≈ 2 years) — [`2026-08-01-size-budget.md`](2026-08-01-size-budget.md).
- `bun run rebuild` — idempotent data maintenance and migration of old schemas.

**The dashboard**
- The logic was moved out of the inline script into `public/app.js` (an ES module, covered by
  tests).
- One data source (`.f.json`, 97-180 KB gzipped) → **every filter is exact**, honor and any
  day threshold included. The nicknames are not fetched at all until a player search exists.
- Fixed: the race when switching snapshots, `fileInfo` pointing at the wrong file, the
  duplicate `value=""` in the preset, `checked = "true"`, the missing debounce (now 150 ms
  plus `chart.update()` instead of `destroy()`/`new Chart()`).
- Added: a loading state and an empty state, `:focus-visible`, a media query below 720 px,
  state in the URL (the button copies a link to the view, not to the raw JSON), an activity
  distribution.
- Chart.js vendored locally — no more CDN without SRI.
- Removed: the "Filtruj" button, `getSelectedProfessions`, the legacy accessors, `json.data`.

**The repo**
- `server.ts`: path normalisation — no more path traversal.
- `.claude/settings.local.json` taken out of git, `luvia` added to the worlds, `404.html`,
  `.nojekyll`, a favicon, CI (`bun test` + `tsc --noEmit`), scripts in package.json.

**Verification status:** 61 tests pass, typecheck clean, the dry run is 21/21 worlds OK. The
dashboard's DOM layer was not exercised in a browser (no browser available in this session) —
what is covered instead is every counting function and the agreement between `el(...)` and
the markup.
