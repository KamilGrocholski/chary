# Audit #3 — margostat (2026-08-04)

An audit after the views were merged (`6d9b8e4`, the same day) and the first look at the
server side since [`2026-08-01-audit-2.md`](2026-08-01-audit-2.md). Three independent
passes — two by machine, one by hand — found **eight real bugs, not one of which was caught
by the 165 tests**, plus two tests that would have turned red on the next scrape.

The worst finding was not in the production code but in what holds it.

---

## The thing worth starting with: the test was gentler than a browser

After `innerHTML` was replaced on a `<select>`, the DOM stub (`test/dom_smoke.ts`) cleared
the value **only when the previous choice had vanished from the option list**. A real browser
clears it **always** — it selects the first option, regardless of what was chosen before.

That one difference hid a bug that made users lose the activity threshold they had chosen:
whoever set "≤ 30 dni" and then narrowed the online filter landed on "< 24h" — a series that
[`2026-08-04-spec-trends.md`](2026-08-04-spec-trends.md) describes as swinging by **14.7%**
while the population is steady at 0.6%. `writeUrlState` then froze it into the copied link.

The order of the fix was: the stub first, then **a test reproducing the scenario** (green,
because nobody had reproduced the scenario), and only then the correction. The test had to go
red first — otherwise there is no proof it holds anything.

The lesson for the future: **a stub more forgiving than a browser produces green tests for
broken code.** Every simplification in `dom_smoke.ts` is worth checking against the question
"is a browser really this lenient".

---

## What held up

So this does not get audited a fourth time:

- **Publishing really does wait for the tests.** `deploy.yml:36` has `needs: check`, and the
  `check` job runs a real `tsc --noEmit` + `bun test`. The promise in the comment is kept.
- **The traversal defence in `server.ts` is correct** — `path.posix.normalize` +
  `path.resolve` + a prefix check, with an edge-case test on `resolved === ROOT`.
- **`innerHTML` is safe.** Only numbers from `toLocaleString`, the `PROF`/`PROF_COLORS`
  constants and file identifiers reach the templates. Nicknames are not fetched anywhere, and
  a separate test holds that.
- **The contrast of `--muted #a0a09a` on `--panel #16161a` is 6.87:1** — AA with room to
  spare. The suspicion was unfounded.
- **The tail of a scrape is not a performance problem.** Measured: reading and `JSON.parse`ing
  all 202 `.f.json` files (61.1 MB) takes 0.51 s, `summarizeSnapshot` over 5.58M rows 0.17 s,
  and together with the manifest ~1.2 s against a round lasting ~1.6 h. Optimising for time
  alone makes no sense.
- **The view state round-trips through the URL in full** — checked for the complete set of ten
  parameters, and the two sets (view and filters) do not collide on keys.
- **Nothing refers to the deleted `public/trends.js`**, and `test/trends.test.ts` has an
  explicit guard for it.
- **The size of the Pages artifact is not a problem for Actions.** `public/` = 137 MB, but
  `upload-pages-artifact` packs a tar.gz — in practice ~49 MB. The limit is 10 GB.
  `actions/checkout` defaults to `depth 1`, so the 178 MB of `.git` is not fetched.

## Fixed in this round

### 1. The history was being fetched several times in parallel

`ensureHistory()` was called straight from the `input` handler, **outside the debounce**.
Typing "250" into Min level is three events in ~200 ms, and the list of missing snapshots is
computed at start — so each of them pulled the same set of files.

Measured against the stub with network latency: **10 of brutal's 11 snapshots fetched twice**.
For gordion that would mean up to 5.7 MB instead of 1.9 MB — the exact opposite of the promise
that transfer is bought knowingly.

The fix came in two parts: a `world → Promise` map in `history.js` (a second call receives the
pass already running) and moving `ensureHistory()` behind the same debounce as the render. A
test counts fetches per URL and requires **exactly one** per file.

### 2. The lost activity threshold

Described above. `fillThresholdSelect` read the select's value **after** replacing
`innerHTML`. The fix is one line — read before replacing — plus a test walking the path
"30d → a 14-day filter → back again". After the fix, narrowing falls to the **widest still
meaningful** threshold (7d), not to the narrowest on the list.

### 3. The previous world's charts on the new world's screen

The first render of a new world arrives only after a snapshot is fetched, so for a few hundred
milliseconds the previous world's series stood under the new heading — tooltips showing those
dates included. On top of that, three early returns from `renderHistory` did not touch the
canvases at all.

The fix: `clearHistoryCharts()` called **synchronously** when the world changes and on every
early-return path. The test samples the state immediately after calling the handler.

### 4. Error states that did not go away

Three separate cases: `progress.failed` survived a return to the default filter (the status
announced "3 not loaded" about a history coming from the complete aggregate); `#error` was not
cleared on the "snapshot already in memory" path, so the banner stayed forever; and the note
about filling in hung on `progress.running`, so a failed fetch made it **disappear**, leaving
an incomplete chart with no word of explanation.

Incidentally: the status said "loading exact data… 10 of 11" even when nothing was in flight
any more. It now says "10 of 11 snapshots · 1 not loaded", and the message about an incomplete
history stands in the HISTORIA section rather than in the error bar 1500 px higher, which is
about the cross-section.

### 5. A missing token guard in `catch`

The success path in `loadSnapshot` checked `token !== snapshotToken`; the error path did not.
Rejecting an abandoned request wiped out a correctly rendered cross-section of another
snapshot.

### 6. `Retry-After: 0` wiped out the pause between attempts

`0 ?? x` is `0`, not `x`. A server answering `429` with `Retry-After: 0` received **four
requests back to back with no pause at all** — straight against rule #5.

The retry policy moved out into a new `src/retry.ts`, because `world_scraper.ts` runs the CLI
and the whole scrape at the top level of the module — importing it from a test would start a
round. An untested backoff is exactly how this bug survived several months. Now the server's
hint may **lengthen** the pause but never shortens it below the exponential floor.

### 7. The write was not atomic

`Bun.write` is truncate + write. A Ctrl-C at the wrong moment left a truncated `.f.json`, and
`JSON.parse` without a `try/catch` then took down **both** the tail of a 1.6-hour round **and**
`bun run rebuild` — the command meant to repair it. Under rule #6 ("the data cannot be
reproduced") that is the worst class of bug available.

A new `src/atomic.ts` with `writeAtomic()` (`<file>.tmp` + `rename`, atomic on POSIX), used in
all five places that write. Plus a `try/catch` around both `JSON.parse` calls with a warning
naming the file: one corrupted snapshot does not take the other 201 with it.

### 8. The CLI did something other than what it was asked, and did not say so

Three holes, and note that `--drop-threshold` and `interval` **were** validated correctly —
what was missing was validation where the author had not thought of it:

| invocation | was | is |
|---|---|---|
| `scrape ../../tmp/x` | snapshots written **outside `public/`** | exit 1 |
| `scrape ,` | an empty list, **exit 0**, "✓ 0/0 worlds" | exit 1 |
| `scrape --dryrun` (a typo) | **a full scrape**, ~1.6 h, 202 overwritten files | exit 1 |

The last case is exactly the class of failure rule #3 is about. Checked live: all four variants
rejected, nothing written, and `--dry-run aether` still works.

### 9-10. Two tests tied to live data

`expect(out.summary).toContain("−5,3%")` — a literal computed from today's fobos. The first
`bun run scrape` would have made red CI on a data commit. The value is now computed from the
published `trends.json` at test time.

`expect(change).toBeLessThan(0.05)` — **it forbade the existence of a snapshot that
`checkPopulationDrop` (the same 0.05 threshold) is meant to detect and write**. The first
genuinely truncated scrape would have produced a correctly set `suspect` flag and a red build
at the same time. The condition is now inverted and thereby **stronger**: a drop past the
threshold is permitted if and only if the snapshot has `suspect === 1`.

### 11. The DOM stub brought level with a browser

Described at the top. Plus: the stub can now return an error for chosen URLs, so the "part of
the history did not arrive" path is exercised in the tests — previously `fetch` always returned
`ok: true` and the rendering of error messages was never checked at all.

**State after the round: 175 tests (was 165), typecheck clean, `scrape:check` passes.**

## Left for later

**`manifest.json` is 100% redundant against `trends.json`.** Checked across all 202 entries:
each has `startedAt`, each path follows from the `worlds/<world>/<id>.f.json` convention, each
is present in `trends.json`, and the world lists are equal. Removing it means −1 fetch and
−5 KB gzip per visit, −82 lines of code, the end of a pass parsing 61 MB for one field, and the
end of a file growing to ~300 KB at the Pages limit (the aggregate this project was built for
is 9 KB for the whole history). The price: the only thing that survives a snapshot without
`startedAt` disappears — and today there is not one such snapshot. **Decision: keep it**,
deliberately, for a round of its own.

**`.n.json` is 74.5 MB, i.e. 55% of the published directory, with no consumer in the browser.**
Cutting it from the Pages artifact would shrink the site to ~62 MB and double the headroom
(~62 → ~120 rounds). **Decision: keep it** — it is the fuel for a player search, and 1.7 years
of headroom is not on fire. The tension with rule #4 is only apparent: this is data that cannot
be reproduced (rule #6), not code.

**Dead code, to be deleted in one move:**
- `ROW_SCHEMA` in `src/parser.ts` — zero consumers, and on top of that it **lies**: it says
  `2` while the files carry `schema: 3`.
- `PROFESSIONS` in `src/parser.ts` — zero consumers, duplicated in `public/shared.js`.
- The `isLegacySnapshot` re-export from `src/manifest.ts` — everyone takes it from
  `snapshot.ts`.
- The `export` on `ACTIVITY_BOUNDS` and `matches` (`public/filters.js`) — the only consumer is
  in their own file.
- ~10 `export`s on types used locally only.
- `SnapshotEntry.file` — a field of the old single-file format; it does not appear in the data.

**The migration layer (~90 lines) is dead in production** — `find public/worlds` turns up not
one file in the old schema. But **delete it only after converting the fixture**:
`test/dashboard.test.ts` and `test/trends.test.ts` put `legacy-snapshot-aether.json` through the
production migration and compare the result against the raw rows. That is the strongest test in
the repo and must not be lost while tidying up.

**`latestSnapshotCount` (`src/snapshot.ts`) sorts by filename**, even though `src/manifest.ts`
carries an explicit comment right next to it explaining why that is off by a timezone. Today
the 3-17 day intervals mask it — no practical effect, but it is an inconsistency with our own
written rule.

**`activityBucket` from `src/trends.ts` has no test with literals** — it is compared against the
copy in `public/shared.js` and against itself. Changing both copies at once passes the whole
suite green.

**Gaps in the static tests** (what they will let through): the `fetch(...)` scan covers only
`app.js` of the four `public/*.js` modules; the external-resources scan skips `404.html`;
`querySelectorAll` in the stub ignores its selector, so a wrong selector is invisible; and
`hidden === false` assertions pass because that is the stub's default — only `=== true` verifies
anything.

**CI/deploy:** `concurrency: cancel-in-progress: true` on the `pages` group aborts a **deploy in
progress** when another push arrives (the official Pages starter uses `false`); there is no
`timeout-minutes` in either workflow (the default is 360 min); the `check` job is duplicated
between `ci.yml` and `deploy.yml` with no mechanism for detecting drift.

**UI, deliberately deferred out of this round's scope:**
- `.toolbar-row2` has no override in the media query, and the "last online" block has
  `grid-column: span 2` — below ~352 px the grid drops to one column and forces a horizontal
  overflow past the card.
- `#onlineNote` (always visible) advertises the "≤ 7 dni and ≤ 30 dni" thresholds even when
  `#thresholdNote` right below it explains why those are precisely what is missing. Two
  contradictory notes side by side.
- The label "**≤ < 24h**" under a `maxDays = 0` filter.
- `profChart` does not mark snapshots carrying the `suspect` flag, though the other two charts
  do.
- `404.html` has `href="/"`, which on project Pages (`/chary/`) leads out of the project.
- The activity preset drifts from the number field: typing 5 leaves the select on "7 dni", so
  the control lies.
- Only `history.replaceState`, so **the back button does not work** — for a view whose main
  function is sharing state, that is a noticeable absence.
- The fixed cost of a visit is **69.8 KB gzip of Chart.js alone**, i.e. 65% of the code loaded.

**Documentation:** `README.md` states 118 MB and ~65 rounds (as of 2026-08-01); in reality it is
137 MB and ~62 rounds. The URL parameter contract is documented nowhere, even though the promise
that old `trends.html` links keep working rests on it. Dated notes cite `file:line`, which goes
stale immediately — worth noting in `docs/README.md`.

## Ideas (value/cost)

1. **`git gc`** — `.git/objects` is 178 MB in **1089 loose objects and zero packs**. Successive
   rounds of the same world differ in a few percent of rows, so delta compression in a pack
   should cut this drastically. The cheapest reduction available: one command, no changes to
   code or data, no effect on CI.
2. **A level percentile** — "I am level 250, where does that put me?". Zero data cost, computed
   from a snapshot that is already loaded anyway. Item #4 on the list from audit #2, untouched
   so far.
3. **A player search** — the only thing that gives the 74.5 MB of `.n.json` a consumer and makes
   "player statistics" finally show a player. Item #1 since audit #1. A cheaper first step:
   searching within **the chosen snapshot** (776 KB gzip for gordion, fetched on demand),
   without progression and without the `charId` seam.
4. **A sticky "Pasuje: N z M" bar + section anchors** — the page is ~2900 px, and the only line
   saying what is actually being filtered scrolls away after ~300 px.
5. **Showing the megabytes while the history is being pulled** — today the status says "3 of 10
   snapshots" and there is nowhere any information about what it costs or how to opt out.
6. **Wrapping `world_scraper.ts` in `import.meta.main`** — today the CLI and the whole scrape
   run at the top level of the module, so no part of it can be imported from a test without
   starting a round. `src/retry.ts` came into being as a workaround.
